# 厂商适配器与模拟联调契约

## 交付内容与限制

`src/production-integrations.mjs` 提供内部标准事件、库存快照、持久化实验状态、状态查询/核查以及模拟退款重试流程。`src/production-operations.mjs` 提供订单与运营投影。后台调用这些服务而不是把供应商字段写死在页面里。

这些接口是本系统的内部契约，不是 PVS 或 WsCharge 官方 API。当前唯一可运行的适配模式是 mock；请求 live 模式会明确失败，不会偷偷回退模拟或调用真实设备。没有开放原始供应商报文入口，没有配置或保存供应商凭据。

普通客户的 TEST 租借与管理员联调实验使用不同账本。联调实验不修改真实订单，也不修改客户已经支付的 TEST 押金。接入真实环境时必须将经过核验的供应商适配器接到经过授权的正式订单服务，并完成真实场景验收；不能只把 mock 字段改成 live。

## 库存快照

内部快照包含柜机 ID、在线标记、观测时间及槽位列表；槽位分别包含槽号、充电宝 ID 和 available/empty/fault/unknown 状态。拒绝重复槽位、重复充电宝及自相矛盾的空槽信息。

当前模拟采用 120 秒新鲜度阈值。超过阈值或离线时不宣称可借库存；这只是测试策略，不代表厂商心跳 SLA。空槽必须有明确 empty 证据，不能从缺失充电宝记录推断。

## 标准事件

事件字段及类型由模块导出的 normalizedContract 定义。事件携带唯一 ID、租借 ID、发生时间、顺序号、来源及明确 TEST 标记。接收端核验关联、时间、顺序和重复事件一致性；未知顺序或冲突进入核查，不能强行覆盖已有事实。只保存允许的标准字段，不保存未知原始载荷。

主要流程：押金确认 → 指令被接收 → 取出确认 → 开始计费 → 归还确认 → 费用结算 → 退款提交 → 退款最终结果。

- 指令被接收不会开始计费。
- 未匹配的归还不会结束任意订单。
- 退款提交或受理只进入 pending。
- 成功与失败等最终状态必须来自查询或经过认证的事件，不能由客服备注替代。
- 计费使用保存的测试价格快照和现有计费规则，不把押金和费用重复计作收入。

## 适配器与服务边界

createIntegrationAdapter 暴露库存、原支付、原退款、原指令及核查结果查询，以及受限制的模拟指令/退款接口。管理业务调用 reconcileIntegrationRun 和 retryIntegrationRefund 等持久化服务，页面不得自行写资金状态。

结果未知时先查询原交易/原指令，禁止盲目重发出宝或退款。仅确认失败的模拟退款才允许重试；重试仍需幂等键，并且被受理后保持 pending，随后查询最终结果。重复请求不能重复改变账本。不同 key 不意味着可以绕过状态限制。

这些契约对真正外部副作用的可靠性并不构成保证。正式适配器还必须提供持久化发送记录、外部交易幂等、回调验签、超时和重试策略、崩溃恢复及对账，不能依赖浏览器一直打开。

## 管理 HTTP 接口

- GET /api/admin/integrations：联调状态、库存、实验订单、支付退款、异常和契约说明。
- POST /api/admin/integrations/scenarios：只接受预定义 scenario；必须带 Idempotency-Key。
- POST /api/admin/integrations/runs/:id/reconcile：空请求体，幂等查询原状态并核对结果。
- POST /api/admin/integrations/runs/:id/retry-refund：空请求体，幂等重试已查询确认失败的模拟退款。
- POST /api/admin/integrations/exceptions/:id/resolve：记录处理备注；不会伪造付款、取出或归还结果。

写操作仅 owner/operator，可读权限不等于可执行权限。会话、同源、CSRF 和速率限制沿用正式后台。没有匿名 webhook 或公开设备操作端点。

实验预设包括已付款未出宝、取出状态未知、归还未匹配、退款处理中、退款失败和成功。实验数量有上限；达到上限时应使用独立测试数据库继续测试，不能清空或替换运行中的业务数据库。

## 后续需要提供的真实资料

WsCharge：传输协议、服务器接入方式、认证/TLS、机柜与充电宝编号、完整槽位状态、指令关联/查询/重试规则、取出证据、归还事件身份/时间/顺序、断网补报和心跳规则。现有离线文档解析见 WSCHARGE.md。I65/S200 不能被假定为已取出，I66 原始消息不能直接触发自动退款。

PVS：准确服务商与 API 文档、测试环境、商户账户、押金收取方式、部分退款及退款查询能力、签名/回调/幂等、金额币种与结算对账规则。没有资料前不假定存在预授权、退款到账时限或特定付款方式。

正式上线还需真实 Google 配置、合法 TLS、测试机柜和受控测试账户、真实小额支付/退款验证，以及异常回放、备份恢复和对账验收。密钥只通过安全配置渠道保存，不进入聊天、源码或本文件。
